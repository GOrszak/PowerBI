# DAX Learning Path for Mid-Level Power BI Developer

## Phase 1 - Model and base measures
- Build the star schema.
- Hide technical keys.
- Create base measures only, not calculated columns unless needed.
- Validate totals by year, category, store and country.

## Phase 2 - Contexts and CALCULATE
- Compare measures in cards, matrices and slicers.
- Practice changing filters with `CALCULATE`.
- Learn when filters overwrite and when they intersect.
- Use inactive date relationships for shipped and delivered sales.

## Phase 3 - Business patterns
- Sales share by category, brand and country.
- Running total and YTD/QTD/MTD.
- ABC/Pareto product classification.
- Working-day sales.
- Budget variance at monthly category grain.
- Currency conversion using rates.
- Customer segmentation.

## Phase 4 - Advanced relationships and hierarchies
- Parent-child employee hierarchy with `PATH`.
- Account hierarchy and unary operator logic.
- Many-to-many customer/product interests.
- Virtual relationships with `TREATAS`.

## Phase 5 - Performance and developer habits
- Use DAX Studio.
- Compare `SUMX` over fact table vs pre-aggregated/filter-friendly measures.
- Avoid high-cardinality columns in visuals.
- Test each measure in isolation before blaming Power BI, the network, the moon, or capitalism.
